GitHub OAuth 授权码流程（rovortex 实际实现）

浏览器全程只接触 code（一次性票据）；access_token 只在服务端 ↔ GitHub 之间流动

客户端 rovortex 服务端 GitHub 安全检查点
为什么入口链接不带 token：授权发生前不存在任何可带的凭据——code 是 GitHub 在第 ④ 步授权完成后才签发的； access_token 只在第 ⑥⑦ 步服务器之间出现，从不经过浏览器； 你最终拿到的 JWT 是 rovortex 自己在第 ⑩ 步签的本地会话，与 GitHub 无关。 state 的角色：它不标识用户，只证明「这次回调来自我发起的那次请求」——防止攻击者把自己的 code 塞进你的浏览器完成登录（login CSRF）。
